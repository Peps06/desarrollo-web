## 1. Introducción

Este documento define los requerimientos **funcionales (RF)** y **no funcionales (RNF)** del sistema "Bitácora de viajes colaborativa". Cada requerimiento tiene una historia de usuario (HU) del backlog y a su responsable, e incluye el flujo ideal, los errores, excepciones y casos de concurrencia que deben cumplirse en la implementación.

**Convenciones generales:**

- API REST bajo `/api`, JSON en camelCase, fechas ISO (`yyyy-MM-dd`) y montos con 2 decimales.
- Códigos de respuesta: 200/201 éxito, 400 validación, 401 sin sesión, 403 sin permiso, 404 no existe; errores con formato `{codigo, mensaje}`.
- La identidad del usuario siempre se toma de la sesión (Principal), nunca de un id enviado por el cliente.

## 3. Requerimientos no funcionales (RNF)


| ID     | Requisito no funcional              | Flujo ideal                                                                                                                                                                                                                                                 | Errores / excepciones / concurrencia                                                                                                                                                                               | HU / Responsable                 |
| ------ | ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------- |
| RNF-01 | Arquitectura de 3 capas             | Presentación (HTML, CSS, JavaScript, Thymeleaf y fetch), lógica de negocio (Java + Spring Boot con validación de entradas) y acceso a datos (JPA + MySQL) separadas por responsabilidad                                                                     | La separación reduce el acoplamiento y facilita mantenimiento y pruebas; la lógica de cálculo vive en servicios (PresupuestoService, BalanceService), no en controladores                                          | HU-03, HU-07 / Equipo            |
| RNF-02 | Entorno WSL reproducible            | JDK 17+, Maven, MySQL y Git instalados y verificados en el WSL de los 5 integrantes; ./mvnw spring-boot:run crea las 7 tablas al iniciar                                                                                                                    | Excepción documentada: MySQL no arranca solo al abrir la terminal, se inicia con sudo service mysql start; verificación con java -version, mvn -v, mysql --version, git --version y SHOW TABLES                    | HU-02, HU-42 / Alfonso           |
| RNF-03 | Seguridad y control de acceso       | Contraseñas con hash BCrypt, sesión con Spring Security, rutas protegidas por defecto y solo participantes autorizados consultan o modifican cada viaje                                                                                                     | La identidad siempre sale de la sesión, nunca del cliente; application.properties fuera del repositorio (solo el .example sin credenciales); login incorrecto no revela si falló el correo o la contraseña         | HU-08, HU-09 / Dana              |
| RNF-04 | Integridad de datos y concurrencia  | UNIQUE (viaje, usuario) en participante\_viaje, UNIQUE (actividad, usuario) en voto, correo único en usuario; reglas de borrado definidas en el ER                                                                                                          | Las restricciones de MySQL respaldan las validaciones ante peticiones simultáneas; operaciones multi-tabla en @Transactional; quitar un participante no borra sus gastos y borrar una actividad sí borra sus votos | HU-04 / Dana                     |
| RNF-05 | Rendimiento y precisión de cálculos | DTOs en lugar de entidades JPA, JOIN FETCH o consultas agrupadas, filtros en el repositorio (Specification o @Query)                                                                                                                                        | Evitar N+1 en el detalle del viaje; cálculos financieros con BigDecimal a 2 decimales para evitar errores de redondeo; sin gastos nunca hay división entre cero                                                    | HU-12, HU-16 / Diego y Alfonso   |
| RNF-06 | Interfaz CSS propia y responsive    | CSS propio (sin Bootstrap ni frameworks) con variables de paleta y tipografía, clases compartidas (tarjeta, tarjeta-dia, btn, barra-presupuesto, mensaje-exito, mensaje-error, insignia-ganadora) y media queries para laptop (≥1024 px) y tablet (≤768 px) | Estados visuales definidos: barra verde, amarilla y roja; saldo a favor en verde y deuda en rojo; solo se editan estilos: si hace falta cambiar HTML ajeno se pide a su responsable                                | HU-06, HU-35 / Citlaly           |
| RNF-07 | README reproducible                 | Instalar, configurar MySQL y ejecutar siguiendo solo el README: git clone, application.properties.example, usuarios de prueba, URL localhost:8080 y cómo correr las pruebas                                                                                 | Sección de problemas comunes (MySQL apagado, puerto ocupado, versión de Java); se comprueba clonando en un WSL limpio distinto al de desarrollo y corrigiendo cada paso faltante                                   | HU-41, HU-42 / Citlaly y Alfonso |
| RNF-08 | Flujo de trabajo Git                | main protegida sin push directo, una rama feature/hu-XX-nombre por historia, pull request con al menos una revisión de otro integrante y commits con prefijo "HU-XX:"                                                                                       | Definition of Done publicada: probado con cURL o navegador, commit "HU-XX: ...", pull request revisado por otro integrante y fusionado a main; git log muestra commits de los 5                                    | HU-01 / Alfonso                  |
